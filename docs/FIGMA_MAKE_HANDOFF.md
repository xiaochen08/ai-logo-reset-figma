# Figma Make 设计任务

你正在重设计光影盒子「智能加 LOGO（重置版）」。请先运行本项目，查看所有页面并点击每个实际入口。当前 Vue 页面来自原产品，演示 API 在 mockBackend.ts 中。目标是提升专业摄影师批量加 LOGO 的效率、可理解性和操作反馈。

## 设计范围

1. 项目大厅、空状态、项目卡片及入口
2. 工作区的照片列表、中央画布、图层与属性面板、顶部工具条和状态栏
3. LOGO 素材库、公共素材、图层锁定/编组/多选/排序、锚点、比例、旋转、阴影和透视
4. 人脸避让、主体前置的操作提示及识别状态
5. 裁切、翻转、拉直、横幅（外扩、内嵌、宽银幕）
6. 跨项目预设、当前照片同步到多张、批量导出与进度/取消/失败提示
7. 新手引导、错误状态、键盘快捷键、动画和鼠标交互

## 视觉约束

保留光影盒子的桌面摄影工具气质：深色画布、黄色主色、清晰层级、真实的摄影预览与顺滑但克制的动效。优先让照片获得可用画布面积。常用操作可以一两步完成，次级选项按任务组织。兼顾 1366×768、1920×1080 和宽屏。

## 关键交互规则（必须明确体现）

- 当前照片、选中多张与「同步到全部」是三个不同作用域，每次批量应用明确显示目标张数。
- LOGO 图层的坐标与尺寸由裁切、横幅之后的最终画布计算；调整背景画布后不能悄悄改变已有 LOGO 的相对规则。
- 锁定图层不可移动或编辑，隐藏图层不得出现在导出合成里。
- 预设保留 LOGO、图层编组、避让/主体前置和可选横幅；每张照片自己的裁切保留。
- 导出必须保留原格式/JPG/PNG/WEBP、画质、原尺寸/最长边、照片锐化、范围选择、缺失 LOGO 提示、任务进度与取消。
- 编辑支持撤销/重做、鼠标拖动、键盘移动、Shift/Ctrl 多选、空状态与失败提示。
- 识别失败要有反馈并可重试；生产逻辑由原软件的服务执行。

## 交付标准

- 先对现有操作流程做页面/组件清单和交互分析，再实施新 UI。
- 所有页面与关键弹窗都可以通过交互实际打开；切换照片、设置、图层、预设和导出可以在模拟数据下演示。
- 明确每个新增 UI 事件对应的 `actions` 或 IPC 方法；功能重排可以，不能默默删除。
- 改动按组件提交到独立分支并发起 PR，提供截图、关键操作录屏或复现步骤。
- 若改用 React，请交付 React 设计实现与事件/状态映射文档；Codex 将在 Vue 原工程中按设计重建。
- 不实现真实扣费、服务器识别、真实文件输出，不上传任何真实照片。
